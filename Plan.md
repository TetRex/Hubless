# Hubless — лёгкая замена G Hub для Windows

> План для Claude Code: читай целиком перед началом, выполняй по фазам, после каждой фазы останавливайся и показывай результат.

## 1. Цель

Трей-приложение для Windows, которое управляет основными функциями трёх устройств Logitech без G Hub:

| Устройство | Связь | Что нужно |
|---|---|---|
| PRO X Superlight 2 (мышь) | Lightspeed-ресивер / USB-C | батарея, DPI (включая раздельные X/Y, если есть), частота опроса, lift-off, onboard-профили |
| PRO X TKL Lightspeed (клавиатура) | Lightspeed-ресивер / USB-C | батарея, RGB (эффекты + статичный цвет), Game Mode и список блокируемых клавиш |
| PRO X Wireless (гарнитура) | свой USB-адаптер | батарея, sidetone, таймер автоотключения |

Мышь и клавиатура могут быть спарены с одним ресивером (2:1) — поддержать оба варианта: общий ресивер и отдельные.

## 2. Нефункциональные требования (главное)

- **В простое (панель закрыта): < 15 МБ RAM, ~0% CPU.** С открытой панелью: < 40 МБ. Никаких циклов опроса с короткими интервалами. Всё событийное.
- Батарею опрашивать не чаще раза в 5 минут + реагировать на HID++-уведомления от устройств.
- Hotplug через `WM_DEVICECHANGE` / `RegisterDeviceNotification` в скрытом окне, а не через периодический перебор.
- Панель управления (раздел 7) открывается по клику на иконку в трее **быстрее 150 мс**. Она живёт в том же процессе: окно создаётся лениво при первом открытии и уничтожается, если панель скрыта дольше 60 с. Пока панели нет, UI не держит ресурсы и не перерисовывается.
- Один exe, без установщика на первом этапе. Конфиг в `%APPDATA%\Hubless\config.toml`, логи в `%LOCALAPPDATA%\Hubless\logs`.
- Автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (переключатель в меню трея).

## 3. Стек

- **Rust** (stable, target `x86_64-pc-windows-msvc`).
- `hidapi` — доступ к HID.
- `tray-icon` (+ `muda` для меню) — иконка и меню трея.
- `windows` crate — скрытое окно, `WM_DEVICECHANGE`, DWM-атрибуты окна панели, системная тема и акцентный цвет, toast-уведомления.
- **Slint** — UI панели. Стиль `fluent`, **software renderer** (меньше памяти, чем OpenGL/Skia, для маленькой панели скорости хватает). UI описывается в `.slint`-файлах.
- `serde` + `toml` — конфиг.
- `tracing` + `tracing-appender` — логирование с ротацией.

Если какой-то крейт мешает целевому потреблению памяти — предложи замену, но не меняй стек молча.

## 4. Архитектура

```
┌──────────────────── hubless.exe ──────────────────────┐
│ main thread: Slint event loop (качает Win32-сообщения)│
│   ├─ tray icon + context menu                         │
│   ├─ hidden window (WM_DEVICECHANGE, WM_SETTINGCHANGE)│
│   └─ панель управления (создаётся по требованию)      │
│            ▲ состояние устройств / команды            │
│            │ каналы (crossbeam / slint::invoke_from_event_loop)
│ device manager (отдельный поток)                      │
│   ├─ hidpp::Transport (на каждый ресивер/кабель)      │
│   │    └─ reader thread (blocking read, timeout)      │
│   ├─ devices::Mouse / Keyboard  (HID++ 2.0)           │
│   └─ devices::Headset (свой протокол)                 │
│ config store (TOML)                                   │
└───────────────────────────────────────────────────────┘
```

Структура крейта:

```
src/

  tray/              # иконка, меню, автозапуск, уведомления

  hidpp/

    message.rs       # short/long/very long отчёты, ошибки
    root.rs          # 0x0000 Root, 0x0001 FeatureSet
    features/        # по файлу на фичу
  devices/

    keyboard.rs

  config.rs

```

## 5. HID++ 2.0 — заметки и подводные камни

- VID Logitech: `0x046D`. HID++ живёт на vendor-коллекциях с usage page `0xFF00`.
- Отчёты: short `0x10` (7 байт), long `0x11` (20 байт), very long `0x12` (64 байта).
- Формат: `[report_id][device_index][feature_index][function<<4 | sw_id][params...]`.
- `device_index`: `0xFF` — прямое проводное подключение или сам ресивер; `0x01…0x06` — устройства за ресивером.
- **Windows-специфика:** hidapi на Windows открывает каждую top-level collection как отдельный путь. Short и long отчёты обычно в разных коллекциях (usage `0x0001` и `0x0002` на page `0xFF00`). Нужно открыть обе: писать в ту, что поддерживает нужный размер, читать ответы с обеих. Это самая частая причина «устройство не отвечает».
- Используй ненулевой `sw_id` (например `0x0A`), чтобы отличать ответы на свои запросы от асинхронных уведомлений устройства (у них `sw_id = 0`).
- Ошибка HID++ 2.0 приходит с `feature_index = 0xFF`; ошибка HID++ 1.0 — с `sub_id = 0x8F`. Обрабатывать обе.
- Таймаут на запрос ~1 с, один повтор. Устройство за ресивером может спать — отсутствие ответа это не фатальная ошибка, а состояние «offline».
- Индексы фич у каждого устройства свои: всегда получать через Root `GetFeature(feature_id)` и кешировать на время сессии.
- Подключение/отключение устройств за ресивером приходит уведомлениями от ресивера (HID++ 1.0 device connection) — по ним переинициализировать устройство.

### Ожидаемые фичи (проверять по реальному дампу, не доверять списку слепо)

| ID | Назначение |
|---|---|
| `0x0000` | Root |
| `0x0001` | FeatureSet (перечисление фич) |
| `0x0003` | Информация о прошивке |
| `0x0005` | Имя и тип устройства |
| `0x1000` / `0x1004` | Батарея (старый / unified) |
| `0x2201` / `0x2202` | DPI / расширенный DPI (X/Y, lift-off — уточнить) |
| `0x8060` / `0x8061` | Частота опроса / расширенная (до 8 кГц) |
| `0x8070` / `0x8071` | Эффекты подсветки |
| `0x8081` | Per-key подсветка |
| `0x8100` | Onboard-профили |
| `0x4522` | Отключение клавиш (кандидат для Game Mode — проверить) |

**Чёрный список:** любые DFU/фичи обновления прошивки (`0x00C2`, `0x00D0` и подобные) — никогда не вызывать.

## 6. Онбординг-профили и режимы

- G Hub часто переводит устройства в host mode. После удаления G Hub устройство может остаться в нём с дефолтными настройками.
- Приложение поддерживает два режима для мыши и клавиатуры:
  1. **Onboard** — настройки записываются в память устройства, работают без приложения.
  2. **Host** — приложение применяет настройки при каждом подключении устройства.
- **Перед первой записью в onboard-память — полный бэкап** всех секторов в `%APPDATA%\Hubless\backups\<serial>-<timestamp>.bin` и возможность восстановить.

## 7. Панель управления

Ориентир по ощущению — флайауты Windows 11 (громкость, сеть, батарея): компактно, быстро, без лишних окон и кнопок «Применить».

### Поведение
- **Левый клик по иконке в трее** — открыть/закрыть панель. **Правый клик** — контекстное меню: «Автозапуск», «Открыть папку логов», «Выход».
- Панель появляется над иконкой у края панели задач. Положение иконки — `Shell_NotifyIconGetRect`, положение и сторона панели задач — `SHAppBarMessage(ABM_GETTASKBARPOS)`. Учитывать панель задач сверху/слева/справа, несколько мониторов и разный DPI (per-monitor DPI awareness v2 в манифесте).
- Окно без заголовка, без кнопки на панели задач (`WS_EX_TOOLWINDOW`), поверх остальных. Закрывается по потере фокуса, `Esc` и повторному клику на иконку.
- Анимация открытия: сдвиг на 8–12 px от края панели задач + fade, ~150 мс, ease-out. Закрытие быстрее, ~100 мс. Учитывать системную настройку «Эффекты анимации» (если выключены — без анимации).
- Все изменения применяются сразу. Слайдеры — с debounce ~150 мс, чтобы не заваливать устройство пакетами. Ошибка записи — короткое сообщение внутри карточки, значение откатывается.

### Внешний вид
- Ширина ~360 логических px, высота по содержимому — до высоты рабочей области монитора (без панели задач и отступов);
  если не помещается, карточки прокручиваются, заголовок остаётся на месте. Скругление 8 px (`DWMWA_WINDOW_CORNER_PREFERENCE`), тонкая рамка и тень как у системных флайаутов.
- Светлая/тёмная тема — по системе (`AppsUseLightTheme`), переключение на лету по `WM_SETTINGCHANGE`. Акцентный цвет — системный.
- Фон: Acrylic/Mica через `DWMWA_SYSTEMBACKDROP_TYPE`, если это корректно работает с прозрачным окном Slint. Если нет или Windows 10 — сплошной цвет из темы. **Сначала сделать сплошной вариант**, эффект фона — отдельной задачей.
- Шрифт `Segoe UI Variable` (fallback `Segoe UI`), иконки `Segoe Fluent Icons` (fallback `Segoe MDL2 Assets`) — системные, не вшивать в exe.
- Все цвета, отступы, радиусы и длительности анимаций — только из `theme.slint`, никаких литералов в компонентах.

### Раскладка
```
┌─────────────────────────────────────┐
│ Hubless                  [профиль ▾]│
├─────────────────────────────────────┤
│ 🖱 PRO X Superlight 2   Lightspeed  │
│ ▰▰▰▰▰▰▰▱▱▱ 72%                       │
│ DPI  [400][800][1600][3200]         │
│ Опрос  ( 1K | 2K | 4K | 8K )        │
│ ▸ Ещё: lift-off, X/Y                │
├─────────────────────────────────────┤
│ ⌨ PRO X TKL            USB-C ⚡     │
│ Подсветка [вкл]  ● ● ● ● ● [+]      │
│ Яркость ━━━━━━━○━━━                 │
│ Эффект [Статичный ▾]  Game Mode [ ] │
├─────────────────────────────────────┤
│ 🎧 PRO X Wireless      не подключено│
└─────────────────────────────────────┘
```
- Карточка на устройство: иконка, имя, тип связи, полоска заряда с процентом и значком зарядки.
- Отключённое устройство — свёрнутая серая карточка «не подключено», без контролов.
- Показывать только то, что устройство реально поддерживает по таблице фич (например, 4K/8K — только если есть в `0x8061`).
- Редкие настройки (lift-off, раздельные X/Y, список клавиш Game Mode, выбор onboard/host) — в раскрывающемся блоке «Ещё» внутри карточки, а не в отдельном окне.
- Полная навигация с клавиатуры (Tab, стрелки, Enter/Space).

### Иконка в трее
- Монохромная, под светлую и тёмную панель задач, плюс маленький индикатор, если у какого-то устройства заряд < 15%.
- Tooltip: заряд всех подключённых устройств одной строкой на устройство.

## 8. Гарнитура

- Протокол не совпадает с HID++ 2.0 мыши/клавиатуры. Опорная реализация — Logitech G PRO в проекте HeadsetControl (батарея, sidetone, inactive time).
- Blue VO!CE, DTS:X и эквалайзер **вне скоупа**: это программная обработка звука в G Hub, а не команды устройству. В README упомянуть Equalizer APO как альтернативу.

## 10. Правила работы для Claude Code

- Работай по фазам ниже. В конце каждой фазы: что сделано, как проверить, какие вопросы.
- **Чтение с устройств можно запускать самостоятельно** (`--dump`, опрос батареи), если ты работаешь на машине с подключёнными устройствами.
- **Любую запись в устройство** (DPI, подсветка, onboard-память, Game Mode) сначала покажи мне как hex-пакеты и дождись подтверждения — до тех пор, пока соответствующая фича не проверена вручную.
- Не угадывай параметры недокументированных функций. Если данных нет — предложи процедуру сниффинга (раздел 12) и попроси меня снять дамп.
- По UI: после каждого заметного изменения панели делай скриншот (или проси меня) и сверяй с разделом 7.
- Перед запуском убедись, что G Hub остановлен (процессы `lghub`, `lghub_agent`, `lghub_updater`); если запущен — предупреди, не убивай без спроса.
- Логи HID-трафика в hex по уровню `debug`, выключены по умолчанию.

## 11. Фазы

### Фаза 0 — Каркас
- Rust-проект, CI-сборка `cargo build --release`, `clippy` без предупреждений.
- Иконка в трее, контекстное меню: «Автозапуск» (галочка), «Открыть папку логов», «Выход».
- Пустая панель на Slint: открытие/закрытие по левому клику, позиционирование у иконки, закрытие по потере фокуса, тема по системе. Без устройств — заглушки карточек.
- Конфиг, логи, автозапуск, single-instance (mutex).
- **Готово, когда:** exe стартует, висит в трее, панель открывается быстрее 150 мс в правильном месте (проверить с панелью задач внизу и сбоку, на двух мониторах, если есть), в простое < 15 МБ и 0% CPU (Диспетчер задач), выход корректный.

### Фаза 1 — Ядро HID++ и диагностика
- Транспорт с учётом раздела 5, сопоставление ответов по `sw_id`.
- Обнаружение ресиверов и проводных устройств, опрос слотов 1–6.
- `hubless.exe --dump` — для каждого устройства: имя, тип, прошивка, полная таблица фич (индекс, ID, версия, флаги) в консоль и в JSON-файл.
- **Готово, когда:** дамп мыши и клавиатуры работает и через ресивер, и по кабелю. Дамп приложить в `docs/devices/`.

### Фаза 2 — Мышь
- Батарея, DPI (уровни, текущий), частота опроса, lift-off, onboard-профили (чтение, бэкап, запись).
- Иконка трея показывает уровень заряда (tooltip + меню), toast при < 15%.
- **Готово, когда:** настройки меняются из CLI-подкоманд (`hubless mouse dpi 1600` и т.п.) и переживают переподключение.
- **Отложено: запись частоты опроса.** `0x8061` setReportRate (функция 3) мышь подтверждает, но частота не меняется
  (проверено 2026-10-19 через ресивер `C54D`: запись 500 Гц → чтение 1000 Гц). Чтение и список частот работают.
  До выяснения причины частота не сохраняется в `devices.toml` и не применяется в режиме host;
  следующий шаг — захват трафика G Hub по процедуре из раздела 12.

### Фаза 3 — Клавиатура
- Батарея, подсветка (выключить / статичный цвет / встроенные эффекты), яркость, Game Mode и набор блокируемых клавиш.
- Per-key подсветка — только в режиме по проводу, в радиорежиме отключена (батарея и полоса).
- **Готово, когда:** то же, что в фазе 2, через CLI.
- Подсветка — как в Solaar: Hubless забирает управление `0x8071` и сам гасит подсветку при простое
  (простой → сон → пробуждение проверены 2026-10-19 через ресивер `C547`).
- Встроенные эффекты (Breathe/Cycle/Wave/Ripple) — раскладка параметров по Solaar `LEDEffects`; у клавиатуры
  версии с насыщенностью (0x15–0x17). Проверены вручную 2026-10-19 через ресивер (дыхание, цикл, волна влево, рябь).
- **Отложено: Game Mode.** У клавиатуры нет `0x4522`, кандидат — `0x4523`, протокол не описан;
  нужен захват трафика G Hub (раздел 12). Per-key `0x8081` — после Game Mode.

### Фаза 4 — Гарнитура
- Обнаружение адаптера, батарея, sidetone, таймер автоотключения.
- **Готово, когда:** работает через CLI, гарнитура появляется/исчезает в трее при включении/выключении.
- Гарнитура — PRO X 2 LIGHTSPEED на протоколе Centurion (не HID++), раскладка sidetone (`0x0604`) и автоотключения
  (`0x0108`) — по HeadsetControl. Чтение и запись проверены вручную 2026-10-19 (CLI `hubless headset`).

### Фаза 5 — Панель управления
- Карточки устройств по разделу 7, подключённые к `state.rs`. Обновление UI только по событиям изменения состояния.
- Блоки «Ещё», debounce слайдеров, ошибки внутри карточки, клавиатурная навигация.
- Затем отдельной задачей: Acrylic/Mica-фон и анимации открытия.
- **Готово, когда:** всё из фаз 2–4 доступно из панели; после 50 открытий/закрытий подряд память в простое возвращается к прежнему уровню (± 2 МБ); при открытой, но неактивной панели CPU ~0%.
- Замер 2026-10-19 (release, `opt-level = "z"`): после 50 циклов и уничтожения окна прирост 0,12 МБ
  (private 4 МБ); CPU 0 мс за 10 с и в простое, и с открытой панелью; первый кадр — 35 мс при создании
  окна, 12 мс при повторном открытии. Осталось: Acrylic/Mica и анимации открытия.

## 12. Процедура сниффинга (для неизвестных функций)

1. Установить USBPcap + Wireshark, запустить G Hub.
2. Начать захват на нужном root hub.
3. Изменить **ровно одну** настройку в G Hub, подождать 2 с, изменить её же на другое значение.
4. Сохранить `.pcapng`, положить в `captures/` с понятным именем (`mouse_dpi_800_to_1600.pcapng`).
5. `python tools/pcap2hidpp.py captures/<file>` — выводит HID++ пакеты с расшифровкой индексов фич по сохранённому дампу из фазы 1.
